# WORKS 破損写真：Google Drive 保存テスト（第2段階）

このフォルダの `Code.gs` と `Index.html` は **Apps Script に登録するためのテストコード** です。既存の `camera-test/index.html` は変更しません。

## 目的
- テスト用JPEG画像を「伝票 1枚 + 破損写真最大49枚」の順で、1枚ずつ Google Drive に保存
- 送信の成否と保存済み枚数を確認
- 通信障害時は保存済みを照会し、ユーザー操作で未送信分を再開（自動再送なし）
- 既に保存された番号の画像を二重保存しない

## 初期設定（操作者が必要）
1. Google Drive で **専用のテストフォルダ** を作成。既存の顧客用写真フォルダは指定しない。
2. 新規の **単独 Apps Script プロジェクト** を作成する。QR在庫管理のGASには追加しない。
3. `Code.gs` に本フォルダの Code.gs をコピー。`Index.html` というHTMLファイルを作り内容をコピー。
4. プロジェクトの「スクリプト プロパティ」に `TEST_ROOT_FOLDER_ID` を設定。値は手順1のフォルダID。
5. Webアプリとしてデプロイ。**実行ユーザー：自分**。アクセス範囲は可能な限り限定し、匿名公開しない。
6. WebアプリのURLにアクセスして、架空の伝票画像+テスト写真で試す。

## 注意
- これは動作試験用です。実際の伝票・顧客情報は使用しないでください。
- 現時点では既存の連続撮影テスト画面と未連結です（次工程）。
- ブラウザー更新後も再開するには、表示されたセッションIDを控え、写真を**同じ順番で**再選択する必要があります。
- 同じセッションIDの同じ写真番号は同じ容量の場合に限り保存済み扱い。**同容量で異なる画像の厳密な同一性はまだ検証していません。** 本番前にファイルハッシュを用いる。
- GAS側では写真1枚5MBまで。実機で通信速度・50枚完了までを確認した後、上限とチャンクを調整する。
- Apps Scriptの `google.script.run` を使うため、このテストUIは **Apps Scriptが配信**します。GitHub Pagesの画面から直接実行する方式ではありません。
- 本番化前に、認証・アクセス制御・監査・重複判定・写真と顧客情報の対応付け・管理表を追加する。
