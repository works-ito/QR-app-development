# 預かり品管理 追加機能仕様（初版・未実装）
更新: 2026-10-30
対象: QR在庫管理 ver.2.2（本番リポジトリ works-ito/QR-app-ver.2）
この文書は開発用ブランチに作成する設計メモ。本番アプリ/GAS/スプシへの変更なし。

## 前提
- 三郷固定。ドライバーが持ち帰った顧客預かり品。
- 異なる顧客・現場の品物を一つのメッシュパレットに混載しない。
- 画面・ラベルで管理番号を要求・表示しない。QRコードも使わない。
- 内部では非表示の一意キーを使用。これは預かり品選択・部分出庫・二重送信防止のため必要。
- AI解析なし。顧客は選択式。現場は既存候補または自由入力、未確認で入庫できる。
- 保管区分は「メッシュパレット」（整数台）と「その他」（品名＋数量/単位/備考）。
- 入庫写真は必須。出庫時は既存写真を閲覧可能。
- 同一顧客・現場でも入庫を勝手に合算しない。必要なら後日関連づけ。
- 出庫: 顧客選択 → 現場選択（未確認あり） → 保管中の預かり品選択 → 数量選択 → 保存。
- 一部出庫可。残数が0で完了、過剰出庫禁止。顧客名/現場名を後日補正できる。

## UI
現行初期画面に「預かり品管理」 → 「入庫」「出庫」「一覧」。
通常QR機能とデータ取得を分離し、既存の初期表示を遅くしない。

## シート案
- 預かり品データ: 内部キー, 顧客キー, 顧客名, 現場, 品名, 保管区分, 数量単位, 現在残数, 状態, 初回入庫, 最終更新, 写真参照
- 預かり品履歴: 履歴キー, 内部キー, 操作, 増減量, 前残数, 後残数, 日時, 操作者, 送信キー, 写真参照
- 預かり品顧客マスタ: 顧客キー, 表示名, 表示順, 有効
- 預かり品印刷待ち: 印刷キー, 履歴キー, ラベルデータ, 部数, 状態, 試行回数, 更新日時, エラー

## 印刷
- スマホの送信一回で、保存確定後にのみ印刷ジョブを作成。
- 三郷Windows PCが印刷待ちを取得し、対応するラベルプリンターへ印刷。
- ラベルは管理番号・QRなし。顧客/現場/品名/区分/入庫日/台数内の識別（例 1/3）。
- 印刷失敗時に預かりデータを二重保存しない。再印刷は印刷ジョブのみ再処理。
- 自動印刷はプリンター購入前にWindowsドライバー/SDK対応・無人印刷方式を検証。
- 印刷完了は実際の紙排出まで保証できない機種もあるため、ジョブ受付と印刷成功を区別。
